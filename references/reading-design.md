# 根据内容选择样式

用户要求和既有模板优先。先理解用途与读者：要顺着看、快速定位、按步骤操作，还是横向对比？再挑选表达方式。文章长度和结构复杂程度比样式数量更重要。正式报告、论文、法律文书和固定模板遵循其规范，不硬加提示框、分栏或分隔线。

| 内容关系 | 合适形式 | 判断和边界 |
|---|---|---|
| 一个相对独立、需要目录导航的主题 | 标题 | 标题描述该节内容；保持层级关系，避免为视觉放大乱选级别。文档标题与正文顶层标题依平台区分。 |
| 同一主题中的小点 | 段落或必要时用加粗短语开头 | 连续出现大量“标题＋一句话”时检查能否在不改变含义、目录链接或阅读顺序的情况下合并；短小章节有独立导航需求时保留。 |
| 解释、叙述、推理 | 连贯段落 | 一段围绕一个意思；太密时按逻辑拆段，不强迫一段一行，也不把推理硬拆成列表。 |
| 必须按先后执行 | 有序列表 | 步骤顺序有意义；编号使用平台真正的列表功能。 |
| 可以并列阅读的条件、要点 | 无序列表 | 项目处于同一层级；大量长条目可考虑短段落，不滥用嵌套。 |
| 真实任务、待办、检查项 | 待办列表 | 平台具备时使用原生可勾选项；不将非任务变成待办。 |
| 多方案按同一维度比较 | 表格 | 简短且可横向比较；每格都是长文时优先段落；保留数据，不为格式强拆。 |
| 原文引述 | 引用 | 与作者自己的说明区分；不把引用框当普通强调或改变引文。 |
| 会影响理解或操作的关键结论、提醒 | 高亮块或少量加粗 | 有明确阅读目的才用；避免每节都用、整段全粗或以颜色作为唯一信息。平台不支持时用清楚的普通段落。 |
| 需要并排比较的短内容 | 分栏 | 各栏内容短且有对照关系，兼顾窄屏阅读；否则按顺序排列或用表格。 |
| 代码、命令、配置、原始输出 | 代码块 | 保留字符和缩进；已知语言时标明。行内代码用于短标识，不把普通文字放入代码块。 |
| 独立内容性质切换 | 分隔线 | 有助于识别边界才使用；平台特定习惯见相应参考。 |
| 有助于理解的过程、关系或数据 | 图表、示意图 | 只在比文字清楚或用户要求时使用；保留来源、标签，保护原有图片。 |

空白是视觉节奏，不是越多越好。考虑平台自身标题和段落间距；避免连续空行、空标题、每段后分隔线。检查移动端是否可读，但没有实际验证时不要宣称已验证。

## 文字强调与颜色

- **加粗**给读者寻找关键结论、重要条件、操作重点或段落短标签。只强调需要关注的词句，不整段全粗、不机械地给每个列表项的开头加粗；避免把普通信息全变成重点。
- **斜体**用于需要轻量区分的术语或作品名，依文档语言和约定使用；中文正文默认少用斜体。重要限制或风险不要只靠斜体传达。
- **行内代码**用于短命令、文件名、配置项、变量等必须准确识别的内容；多行代码、命令、配置或原始输出用代码块，保留字符与缩进，已知语言时标明。普通说明不放代码块。
- **高亮块/颜色块**承载一整段确有阅读价值的结论、提醒或限制。其中文本应简短、清楚且与颜色表达的意思一致；不要给每节导语或每个结论都加框。若是行内文字背景颜色，遵循相同语义但只用在必要的短词句，不把正文整段刷底色。
- **文字颜色**默认使用正常文字色；只有短状态或确需提示的短词句才上色，不以颜色作为信息的唯一来源，也不把整段正文染色。既有文档或用户指定的颜色体系优先，不擅自替换。
- 同一处信息通常选择一种主要强调方式；必要时可在提示块内少量加粗关键词，但不叠加整段加粗、斜体、多种文字颜色和装饰符号。正式材料依模板和体裁处理。

颜色有清楚的语义，但不强制每篇文档用齐；用不到就不使用。平台不支持颜色、对比度不足或深浅模式影响可读性时，采用普通文字或其他可读形式，并保留文字提示。

| 颜色 | 默认含义 | 文字提示示例 |
|---|---|---|
| 蓝色 | 信息、补充说明 | 说明、适用范围 |
| 绿色 | 推荐、已确认 | 推荐、已确认 |
| 黄色 | 注意、待确认 | 注意、待确认 |
| 红色 | 风险、错误、禁止 | 风险、错误、禁止 |
| 灰色 | 中性辅助信息 | 术语补充、参考说明 |

不同平台的具体语法、支持范围与颜色选择由平台参考决定；普通 Markdown 不默认支持彩色文字、背景和高亮块，不为制造颜色而随意引入平台专属语法或 HTML。

## 主动寻找适合的样式

写新文档或在用户授权范围内整理文档时，先看内容需要什么阅读引导，再决定样式。不要只把段落、标题和列表当作默认答案，也不要因为有“克制使用”而从不考虑高亮块、引用或其他平台原生样式。

通读或拟大纲时主动识别下列候选；确认语义、体裁和平台能力后，再选择恰当形式。候选不是插入样式的强制条件，也不为凑样式添加没有依据的结论或引文。

| 看到什么内容 | 主动考虑什么 | 判断与示例 |
|---|---|---|
| 读者理解全文所需的核心定义或最关键结论 | 蓝色说明块或简短导语；必要时局部加粗 | 例如概念入门长文中，用简短说明块帮助读者先抓住核心；如果导语已经足够醒目，不必重复建块。 |
| 容易误解的前提、边界、限定条件或注意事项 | 黄色注意块，或紧贴上下文的简短加粗 | 例如“相关不等于因果”“可能发生不等于已经证实”；让读者在最需要时看到，而非移到很远的位置。 |
| 操作出错可能造成损失，或有明确的禁止事项 | 红色风险块 | 依据实际内容表达风险，不把普通建议夸大成危险。 |
| 适合读者采取的明确做法或已核实结果 | 绿色推荐/确认块 | 区分推荐与事实已经确认；没有根据时不要伪称已验证。 |
| 次要背景、术语补充、阅读范围 | 灰色辅助块或普通段落 | 只有放入块后更容易理解时才用，避免中性说明被框得满页都是。 |
| 真实原文、明确署名或来源的观点 | 原生引用块并标来源 | 确保确实是引文且不改原意；作者自己的总结不伪装成引文。转述可用普通段落并链接来源。 |
| 对象、方案或概念之间可按共同维度对比 | 表格、短分栏或并列列表 | 选择读者容易比较的形式，兼顾窄屏；单条长叙述不强塞入表格。 |
| 必须依次执行的步骤或可并列的事项 | 原生有序或无序列表 | 有先后才编号；不要把本来连贯的论述强拆成清单。 |
| 准确复现的命令、配置、代码 | 行内代码或代码块 | 使用原生格式，保留原始字符、缩进；不要以代码块承载普通引用或正文。 |

写完后按全文再扫一遍：哪些关键定义、注意事项或建议需要读者快速看到？哪些内容有真实引用、清晰比较或操作顺序？若适合用而尚未使用，则优先在内容原位置采用原生样式，保留原话与来源；若没有适合的内容，就不添加。检查高亮块是否每个都有明确作用、颜色含义是否一致，避免重复强调和页面拥挤。不以样式种类或数量凑目标，也不单凭“没有样式”判错。受目标平台或保真限制无法实现时如实报告。

## 主动识别列表和术语

写作时以及交付前，逐节检查段落内部和连续段落，主动找出能独立阅读的步骤、同级事项、术语解释，不要仅看表面是否已有列表符号：

- **顺序有意义**：读者需要按先后完成一组步骤，或阶段依赖前序结果时，优先用真正的有序列表。尤其检查连续出现“第一步、第二步”“首先、然后、最后”的操作段落，以及在一段中用箭头串起的实际步骤。每项保留必要条件和解释；如果语序只是叙事而非操作顺序，可以保留连贯段落。
- **内容平行、顺序不重要**：有多个可分别查看的条件、要点、案例或类型时，优先考虑无序列表。避免把诸如“数据来源、更新频率、权限、版本”等多个各有说明的要点塞进长句或一个长段落；如果只是两三个很短的名词，保持自然短句也可以。
- **术语与定义**：术语速查、多个名称及对应解释，应便于逐项查找。短定义使用无序列表（术语可适度加粗），有多个固定比较维度时使用简单表格；每个术语都需要较长解释时拆为独立段落。不要把一串“术语：定义。术语：定义。”挤成一整段。保留定义、上下文与来源，不自行增删或改写事实。
- **既有文本保真**：仅在所选范围内转换，步骤含义、顺序、条件、引文、链接、评论和资源均需保留；连续编号文字转原生列表时避免数字重复。无法确认顺序或安全保留锚点时保留原样并说明。
- **不机械列表化**：解释、论证、因果关系和有承接的叙述继续用自然段；单项、需要持续阅读的长论述或无明确并列关系的内容无需强制列表。避免每段都变成 bullet，也避免多层嵌套。

自查示例：把“第一步准备资料。第二步提取内容。第三步检查结果。”写成有序列表；把“切片：拆分文档。索引：加快查找。召回：找出相关内容。”分成可逐项查找的无序列表，而不是一个长段落。新文档完成后再检查：明显的操作步骤是否仍是手打编号的普通段落？并列要点、术语是否挤在一段？适合转换时主动转换并核对，确有理由保留则不硬改。

## 交付前检查

针对全文或用户指定的整理范围重新阅读，而不是只问自己“有没有检查过”。逐项定位具体内容、记录选用或不选用的理由，至少在本次任务的工作记录中保留核对依据，不必把检查过程放进用户文档：

1. **重点与边界**：定位核心定义、关键结论、注意事项或风险，判断现有段落、加粗或原生提示块能否让读者看到重点；找到遗漏时按内容与语义选择样式，没有适合候选则记为不适用，不为凑数量加框。
2. **步骤与并列内容**：定位有先后依赖的操作，以及可以独立阅读的要点；判断应使用原生有序列表、无序列表还是保留连贯段落。检查“第一步、第二步”等普通段落有没有漏转；叙述顺序不等于执行步骤。
3. **术语与阅读密度**：检查每个术语说明或要点集合是否可逐项寻找；定义混成一整段时按内容用列表、表格或分段。判断文字墙、连续碎标题、过多强调和密集列表是否影响阅读；不把长解释硬塞进表格或拆散论证。
4. **引用与对照**：存在真实引文时检查引文与来源；存在多方案同维度对比时判断段落、表格或分栏哪种更清楚。没有引文或比较对象时标记不适用，不编造。
5. **平台和保真**：核对用户要求、文档体裁和既有模板；核对适用的编号、间距、原生块、颜色、文本和资源是否实际保留。读不到、未能查看视觉效果或不能保证评论/附件等保真时，明确说明范围和限制，不说全部通过。

发现明显遗漏时仅在授权范围内修正并重查受影响位置；无法安全调整、用户只要求审查或平台不支持时不写入，向用户报告。内容、颜色及样式的适用性按判断决定，不设置固定数量；已有文档保护原文、链接、目录和评论优先。

## 示例

**碎标题：**“背景 / 系统现状 / 使用问题”如果各只有一句且同属现状，可保留一个需要导航的章节，用自然段或小列表承载；原有链接、目录、特殊模板依赖这些标题时不擅自合并。

**先后与并列：**“打开设置、选择目录、保存”有先后，使用有序列表；“支持图片、公式、代码”是并列能力，使用无序列表。

**提示与引用：**“注意：修改前备份”可以是提醒块；引文仍是引用块，并保留来源。高亮框不是引用的替代品。

**避免反效果：**一段中的三个短观点不一定需要三个标题；一段连贯的解释不一定需要三个列表项；页面中已足够醒目的标题旁边不必再加横线、颜色和高亮框。
