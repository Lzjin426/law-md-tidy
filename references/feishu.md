# 飞书文档排版

先按 `lark-doc` 的要求读取 `lark-shared`、fetch、XML、style 和创建或更新工作流。文档操作使用用户身份；修改已有文档前以 full 细节读取目标及相邻结构，局部编辑；结构操作后重新读取 block ID。针对用户的 `law-md-tidy` 约定，本文件和阅读设计中的空白、分隔线、编号与组件选择优先于 `lark-doc` 的一般风格建议；用户指定模板/明确要求仍优先，平台实际能力限制始终适用。

新建飞书文档且需原生编号、空段落或高亮块时，优先按 `lark-doc` 的创建流程使用 DocxXML 直接表达这些结构；Markdown 导入不应被假设能保留原生标题编号和空段落。用户明确要求导入 Markdown 时遵循用户要求，回读后报告未保留之处。创建调用仍在运行、超时或结果未知时，先等待原调用并确认结果；不得因暂时没有输出而重复创建。无法确认结果时停止并说明，避免产生重复文档。

## 标题和编号

- 飞书标题栏是总标题，正文标题承担章节导航；不要重复插入总标题或仅为突出而升高标题级别。依结构逐级组织。已有标题、编号、锚点、目录和交叉引用要保留，除非用户明确要求调整且可保真。
- 是否编号按文档目的判断。新写的长篇学习笔记、需要章节引用的方案和报告默认采用原生标题编号；短笔记可以不编号。已有模板、用户明确要求或其他编号体例优先。新写长篇文档如有不编号的具体原因，应在交付时说明，不要仅因未填写编号属性而默默省略。
- 采用 1、1.1、1.1.1 体系时，使用飞书原生标题编号，绝不通过手打数字和空格伪装。使用 `<h1 seq="auto" seq-level="auto">`，h2/h3 同理；写入前核对当前 lark-doc 能力。该方式属于既有实测的非公开通道，可能变化。使用 XML full 回读检查 `seq`、`seq-level` 和 `seq-marker`，并核对层级和显示；读取不到或操作不支持时不要声称成功。
- 本机飞书样例曾回读到 1、1.1、1.1.1、1.2 和 2 等编号；在一处插入二级标题后，后续二级、三级编号自动顺延，删除后恢复。此结果只适用于当时环境，不能推定所有版本与文档都相同。变更已有标题时检查后续编号、目录和交叉引用；实际检查后才报告自动重排已验证。对用户原有手工编号，未经要求不要整体替换，尤其不要删改语义如“第一章”。

## 空白和分隔线：用户选择的 B 方案

- 一级章节之间默认一条原生分隔线，位于前一章节全部内容之后、下一一级标题之前；短文档、原有模板或内容不适合时可不加。不要在末尾补线，不在标题文字后立刻插线，不叠加多条。
- 相邻二级章节之间默认一个空段落，位于前一二级章节的全部内容之后、下一二级标题之前；二级章节末尾有三级章节时，放在最后一个三级章节之后。不要在每个正文段落之间插空段落。长短文档及原有模板可按阅读节奏调整，避免与原有空白、分隔线叠加。
- 对新写的长篇文档，创作时就显式插入二级章节间的空段落；写后回读逐一检查同一一级章节下相邻二级章节的边界，发现缺失则补齐并再次回读。若平台无法保留空段落或有其他具体原因未按默认执行，交付时说明。
- 既有文档可能直接使用二级或三级标题作为正文顶层。先按它们实际的章节关系、现有布局和阅读节奏判断间距；不要仅凭视觉样式把这些标题当作一级标题，也不要自动提升层级、加线或套二级空行规则。确实需要调整标题层级或涉及目录链接时，先确认用户意图和保真能力。
- 标题和紧随其后的正文一般不另垫空行；表格、图片、代码等块前后视实际拥挤程度适当留白。现有手工排版和用户明确要求优先，局部整理不重排无关区域。
- 原生分隔线和空段落都需按文档结构判断，不能用几个连字符或多个换行冒充。回读确认 `<hr/>` 和空段落是否存在；视觉距离应以实际页面核对，未查看则不声称视觉效果已确认。

## 组件选择与实施

- 有先后操作用飞书原生有序列表，并列事项用无序列表，任务使用原生待办；有真实对照需求用表格。正文解释仍保持连贯段落。
- 依 `reading-design.md` 主动查找散落在连续普通段落中的“第一步/第二步”等实际操作步骤，以及挤在一个段落中的同级要点或术语解释。适用时分别转换为原生有序列表或无序列表；术语也可按情况用表格或独立段落。新写文档优先在生成时直接使用原生块，已有文档仅在能保留内容、顺序、链接和评论等锚点时局部转换。不要把正文伪装成手打列表，也不要强行列表化论证。
- 原文使用引用块，关键结论或提醒在适合的体裁中可以用高亮块；分栏限于适合并排的短内容，不机械规定数量。飞书 `callout` 对内部块类型有限制，详见 `lark-doc` XML 指南。颜色有含义且克制使用；移动端效果未验证须说明。
- 高亮块颜色与文字颜色遵循 `reading-design.md` 的语义，优先使用飞书支持的原生浅背景：信息 `light-blue`、推荐/已确认 `light-green`、注意/待确认 `light-yellow`、风险/错误/禁止 `light-red`、中性 `light-gray`；颜色不是唯一标志，块内要写明“说明”“待确认”“风险”等含义。文字默认保持正常颜色，只有短状态等有需要的内容才使用蓝、绿、黄、红、灰文字；保证可读，不为颜色而改变既有文档中的颜色含义或模板。
- 需要加粗、斜体、行内代码、代码块或文字背景时，遵循通用规则和 `lark-doc` 的 XML 嵌套及平台支持限制；使用真正的原生样式，不用文字标记假装显示。颜色或样式未成功写入或无法回读时如实说明，不保证视觉效果。
- 新写学习文档或整理授权范围内的内容时，依据 `reading-design.md` 主动筛选核心定义、易误解之处、操作风险、推荐做法、真实引用以及可比较内容。适合时在相关内容附近使用飞书原生高亮块、引用块、表格或列表等，保持原文和来源；不要仅因“默认克制”省略有明确阅读价值的样式。每个块应独立有用；不得为了凑样式编造引文或强行上色。
- 已知代码使用代码块并标语言。对公式、链接、代码、原文引述、表格数据不做标点或空格自动替换。公式居中、图片处理、表头样式、首行缩进等依文档体裁、模板与实际需要决定，不为了统一而硬改。
- 优先精准编辑，不使用全文 overwrite；如局部替换无法保留评论、画板、图片、嵌入文件、同步块等资源及其锚点，保留原样并报告。不要把只读或预览当写入授权。
- 回读核实标题层级与原生编号、分隔线、空段落和所有受影响内容；检查链接、表格、图片等与原有内容一致。检查有无适合突出却遗漏的关键定义或注意事项，并核实选用的原生块和颜色是否写入；检查有无仍在普通段落中手打的连续操作步骤或挤成一段的术语要点，适合转换则处理并再次回读，确无需要时无需强加。遇到失败按具体原因停止或安全处理，不反复写入；说明未完成的内容。再次扫描时保持稳定。
- 交付前读取实际写入文档的 full XML，结合 `reading-design.md` 的五项检查定位具体位置：长文标题编号的 `seq`/`seq-marker`，相邻一级章节之间的 `<hr/>`、同一级章节内相邻二级章节之间的空段落，实际步骤对应的 `<ol>`、并列项对应的 `<ul>`，以及决定采用的 `<callout>` 背景色和内容。逐项核对实际块，而不是只看写入命令是否成功；用户指定模板、体裁、短文等不适用情况按实际判断。发现漏写就在可安全处理的范围内补齐并回读；不能核实视觉、资源或某项块时明确说明。
