# 独立检查：内容判断与实际排版

自查和独立检查是两步。独立检查由未参与当前文档写作的 agent 执行，不能由写作者把自己的第二次检查改称“独立”；独立检查仍是概率性的审阅，不保证所有问题都会被发现。

## 发起检查

写作者完成初稿、自查和实际文档回读后，用当前环境可用的 subagent / 独立 agent 工具启动一名只读检查者。只交给它当前任务的用户要求、目标文档或局部范围、适用的 `law-md-tidy` 规则及必要的样式判断证据；不要暴露无关文档，不预先告知希望得到的结论。用户已要求不查看其他文档时，严格只读指定文档。不要发送消息或修改文档。检查者不可仅依赖写作者的结论，必须自行读取实际成果；读不到则报告未验证。

请求检查者逐项输出：通过 / 有问题 / 不适用 / 未验证，每项给出具体位置和判断依据；适用但不使用某种样式时说明为什么普通段落或其他样式更合适；无法判断是否发生过某个写作过程，就标记未验证，不以最终结果冒充过程证据。区分必需规则与建议，不以高亮块、列表或颜色的个数当通过条件。

检查内容：

1. **内容与样式**：从实际正文定位核心定义、关键结论、易误解前提、警示或推荐做法的候选，并判断现有表达能否让读者识别；评估高亮块、加粗或普通段落是否合适。没有候选要说明；确有遗漏时定位原文及理由。检查颜色的语义、是否过度强调、是否依赖颜色传递唯一信息。
2. **列表、术语与结构**：辨认实际步骤与并列事项，检查原生列表或段落是否适合；检查术语密集段落、文字墙、碎标题与过度列表化。无此类内容标不适用。
3. **实际平台格式**：根据文档和任务选择适用规则，飞书读取实际 full XML 检查 `seq`/`seq-marker`、分隔线、二级章节间空段落、`<ol>`/`<ul>`、`<callout>` 和颜色等；只在有适用内容时检查。Markdown 遵循目标环境及原有规则，不套用飞书规则。检查资源、链接、文本和顺序的保留是否有证据；如无修改前记录或无法检查评论、图片等，标记未验证。
4. **范围与视觉**：确认没有改写内容、编造引用或越过用户指定范围；核对文档实际页面效果，如没有查看则标记未验证。只读结构不能证明移动端、视觉布局或原文事实正确。

检查者报告具体位置、当前样式、建议及理由，区分明显缺漏、主观建议、未验证和不适用；不自行改稿，也不把可接受的不同风格判作错误。

## 收到结果后

写作者评估每项发现；明显且能在用户授权范围内保真的问题做最小局部修复，其他保留并报告。修复后回读受影响区域，交原检查者复核修复及可能的连带变化；检查者不可用时说明复核未完成。避免反复试错，不能安全修复或结果仍不确定时停止并说明原因。

若当前环境不提供独立 agent、执行权限不足、用户明确禁止委派，或独立检查者未响应/未读取实际成果：写作者仍须做第二遍只读检查并说明**独立检查未完成及原因**；不得宣称完成独立检查或静默把自查替代为独立检查。不得因为本技能自带检查流程，擅自扩大对他人文档、外部服务或发送消息的授权。
